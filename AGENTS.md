# AGENTS.md — «Нейро-стенографист» (Nuclear IT Hack, Android)

Этот файл читает Codex перед любой задачей. Держи его в корне репозитория.

## 1. Цель
Android-приложение, которое ПОЛНОСТЬЮ локально: импортирует аудио → ASR (русский) → диаризация → тайминги реплик → локальная LLM (ограниченная постобработка) → просмотр → экспорт JSON.
Баллы: текст (WER) 40, спикеры 25, тайминги 10, скорость (RTF) 10, UX 10, защита 5. 75/100 — качество. Любая задача оценивается по влиянию на эти метрики.

## 2. Жёсткие правила (нарушение = задача не принята)
1. Никакой сети. В `AndroidManifest.xml` НЕТ `android.permission.INTERNET`. Никаких HTTP-клиентов, аналитики, crash-репортеров с сетью, загрузки моделей.
2. Все модели лежат в APK (assets, `noCompress`). Ничего не скачивается при первом запуске.
3. LLM НИКОГДА не меняет `speaker_id`, `start_ms`, `end_ms`, число и порядок реплик. LLM может менять только регистр и пунктуацию внутри `text`. Каждый ответ LLM проходит `WordGuard` (нормализованная последовательность слов до/после совпадает), иначе берётся исходный текст.
4. Экспорт строго по контракту:
   ```json
   {"transcript":[{"speaker_id":"speaker_1","start_ms":1250,"end_ms":4380,"text":"..."}]}
   ```
   Инварианты: `0 <= start_ms < end_ms <= duration_ms`; сортировка по `start_ms`; `speaker_id` вида `speaker_N`, нумерация по первому появлению; `text` не пустой после trim; никаких лишних полей.
5. Тайминги считаются только из аудио (таймстемпы токенов ASR + границы VAD/диаризации) в абсолютной шкале исходного файла. Никаких равномерных распределений по интервалу.
6. Не подгоняться под скрытые записи жюри. Тестовые данные — только наши `testdata/`.
7. Число спикеров НЕ хардкодить: автоопределение в диапазоне 1..8.
8. Неречевые звуки (животные, музыка, шум, смех) не порождают реплик и новых спикеров: реплика без слов ASR или из одного неуверенного токена < 300 мс отбрасывается и не участвует в кластеризации.
9. УНИВЕРСАЛЬНОСТЬ ВАЖНЕЕ ПИКОВОГО РЕЗУЛЬТАТА. Записи жюри неизвестны, поэтому:
   - никакой подстройки под домен, лексику, конкретных дикторов или длину файла;
   - пороги подбираются на `testdata/dev`, а метрики отчитываются на отложенном `testdata/test`; конфигурация, выигравшая на одном типе записей и проигравшая на другом, не принимается;
   - критерий выбора конфигурации — лучшее СРЕДНЕЕ и лучший ХУДШИЙ случай по всем условиям, а не рекорд на одном файле;
   - адаптивные решения предпочтительнее фиксированных (число спикеров, громкость, границы реплик);
   - любой шаг (шумоподавление, LLM, сглаживание) включается по умолчанию, только если он не ухудшает ни одно условие тестовой матрицы больше чем на 1 п.п.;
   - на каждом этапе есть безопасный fallback: диаризация упала → один спикер; LLM не уложилась в бюджет → текст ASR; редкий формат → понятная ошибка, а не краш.
10. Любое изменение, влияющее на метрики, сопровождается прогоном `bench` и таблицей до/после в описании коммита/PR.

## 3. Структура репозитория
(Адаптировать под шаблон организаторов github.com/grigorevmp/hacathon_template, если он диктует корень.)
```
app/              Compose UI, Foreground Service обработки, навигация, плеер
core/             ЧИСТЫЙ Kotlin/JVM, без Android: модели данных, Alignment, PostProcess,
                  SpeakerRelabel, JsonExporter, ContractValidator, WordGuard, метрики
engine-audio/     MediaExtractor+MediaCodec → PCM16 mono 16 kHz, ресемплинг, кэш на диске
engine-sherpa/    обёртки sherpa-onnx: VAD (silero), ASR (GigaAM v3), диаризация (pyannote-seg-3.0 + эмбеддинги)
engine-llm/       llama.cpp через JNI/CMake, GuardedEditor, Summarizer
bench/            JVM-харнесс на Mac: тот же core + sherpa-onnx Java API; прогон testdata → JSON
tools/            python: wer.py (jiwer), der.py, boundary_err.py, validate_json.py, report.py
testdata/         наши записи + эталонные JSON (не жюри)
docs/             ARCHITECTURE.md, MODELS.md, LIMITATIONS.md, TEST_RESULTS.md, ADR/
```
Правило зависимостей: `core` ни от чего не зависит; `engine-*` зависят от `core`; `app` собирает всё. Вся логика, которую можно тестировать без телефона, живёт в `core`.

## 4. Конвейер (контракт между модулями)
1. `AudioDecoder` → `PcmFile(path, sampleRate=16000, durationMs)`; float не держать целиком в RAM для длинных файлов — читать окнами.
   Нормализация входа (одинаковая для любых файлов): любые кодеки/частоты/каналы → 16 кГц моно, удаление DC, нормализация громкости по речевым участкам (RMS к целевому уровню, без клиппинга). Шумоподавление по умолчанию выключено — включать только после A/B по всей матрице.
2. Параллельно (2 корутины, раздельные пулы потоков):
   - `Vad` → речевые интервалы → чанки ≤ 25 с с паддингом 200 мс, резать только в паузах;
     `Asr` по чанкам → `List<Word(text, startMs, endMs, conf?)>` в абсолютном времени.
   - `Diarizer` по всему файлу → `List<SpeakerTurn(speakerIdx, startMs, endMs)>`.
3. `Alignment` (core): слово → спикер по максимальному перекрытию с турнами; при нуле — ближайший турн ≤ 300 мс; затем сглаживание (одиночное слово среди чужих → к соседям, кроме «да/нет/угу/ага» с собственным турном ≥ 300 мс).
4. `Segmenter` (core): слова одного спикера склеиваются в реплику; разрыв при смене спикера или паузе > `PAUSE_SPLIT_MS` (стартово 1000). `start_ms` = начало первого слова, `end_ms` = конец последнего (с поправкой на VAD-границу ± `EDGE_PAD_MS`).
5. `SpeakerRelabel` (core): `speaker_N` по порядку первого появления; слияние кластеров с косинусной близостью центроидов > порога.
6. `GuardedEditor` (llm): батчи реплик → только пунктуация/регистр → `WordGuard` → принять/откатить. Таймаут-бюджет на файл; при превышении — оставить ASR-текст.
7. `ContractValidator` → `JsonExporter`.
Все пороги — в одном `PipelineConfig` (data class), чтобы `bench` мог перебирать их.

## 5. Команды
```
./gradlew :core:test                 # юнит-тесты чистой логики (обязательно зелёные)
./gradlew :app:assembleRelease       # APK
./gradlew :bench:run --args="testdata/ out/"   # прогон на Mac
python3 tools/report.py testdata/ out/          # WER / DER / ошибка границ / RTF
adb shell am start -n <pkg>/.BenchActivity --es dir /sdcard/nstest   # прогон на телефоне, лог RTF/RAM
```

## 6. Definition of Done для любой задачи
- компилируется; `:core:test` зелёный; новые ветки логики покрыты тестом;
- нет сети, нет новых тяжёлых зависимостей без ADR в `docs/ADR/`;
- для изменений качества — таблица метрик до/после на `testdata/`;
- для изменений скорости/памяти — замер на физическом телефоне (модель, Android, RAM), не на Mac;
- `ContractValidator` проходит на всех выходах `bench`.

## 7. Роли агентов
Запускай роли последовательно по этапам, а не все сразу. У каждой задачи один владелец, вход, выход и критерий приёмки.

### lead (оркестратор)
Держит ТЗ-чеклист, режет задачи ≤ 2 ч, назначает роль, принимает по DoD. Не пишет большой код сам.
Промпт: «Ты lead. Сверь задачу с ТЗ и разделом 2. Разбей на подзадачи с входом/выходом/критерием. Назначь роли. Отклоняй всё, что не влияет на 75 баллов качества или на работоспособность, до готовности MVP.»

### researcher (спайки и ADR)
Проверяет модели, лицензии, API sherpa-onnx/llama.cpp, размеры, наличие таймстемпов. Выход — короткий ADR с фактами и ссылками, без кода в прод.
Промпт: «Проверь <вопрос>. Только факты с источниками и минимальный воспроизводимый пример. Отметь [Проверить] всё, что не измерено.»

### android-integrator
Gradle, NDK/CMake для llama.cpp, AAR sherpa-onnx, загрузка моделей из assets, Foreground Service, отмена, прогресс, без утечек памяти.
Приёмка: чистая установка на телефон в авиарежиме, обработка 1 файла end-to-end.

### speech-engineer
`engine-audio`, `engine-sherpa`, `core/Alignment`, `Segmenter`, `SpeakerRelabel`. Главная роль для WER/DER/таймингов.
Приёмка: улучшение метрики на `testdata/` без регрессии других > 1 п.п.

### llm-engineer
`engine-llm`: llama.cpp JNI, промпты, `GuardedEditor`, `WordGuard`, `Summarizer`, бюджет времени, выбор модели/квантования.
Приёмка: WER с LLM ≤ WER без LLM; RTF-вклад LLM замерен; 0 изменений слов, прошедших guard.

### eval-engineer
`bench/`, `tools/`, сбор и разметка `testdata/`. Единственный источник правды по метрикам.
Набор строится как МАТРИЦА УСЛОВИЙ, а не под предполагаемый домен; делится на `dev/` и `test/`.
Источники:
- свои записи команды (разные телефоны, комнаты, дистанция до микрофона);
- открытые русские корпуса (Common Voice ru, SOVA, FLEURS ru, OpenSTT) — для ASR; Golos только с пометкой «in-domain для GigaAM»;
- синтетические диалоги: склейка реплик разных дикторов из открытых корпусов с паузами 0–1.5 с и перекрытиями 0–20 % — даёт точную разметку спикеров и времени бесплатно;
- открытые наборы диаризации (VoxConverse, AMI) — для проверки, что кластеризация не сломана на чужом языке/условиях.
Оси матрицы (каждая ось покрыта минимум 3 файлами):
- число спикеров: 1, 2, 3, 5;
- длительность: < 1 мин, 5 мин, 30 мин, 60 мин;
- качество: студия, комната, телефон 8 кГц, шум/музыка (SNR 5–20 дБ), тихая запись, клиппинг;
- голоса: мужские/женские, похожие голоса, синтезированные, стилизованные;
- динамика: короткие ответы, перебивания, долгие монологи, длинные паузы;
- форматы: wav/mp3/m4a/ogg/opus/flac/amr, 8–48 кГц, моно/стерео.
Отчёт: таблица метрик по каждой ячейке + среднее + худший случай.
Приёмка: одна команда выдаёт таблицу WER/DER/границы/RTF по конфигурации.

### ui-engineer
Compose: Импорт (+ запись с микрофона — после MVP, слайд 15 её разрешает) → Прогресс (этапы, отмена) → Расшифровка (цвет спикера, время, тап = воспроизведение с этого места) → Экспорт JSON (SAF) → Протокол от LLM. Минимум экранов, ноль сетевых библиотек.

### reviewer
Ревью каждого диффа: правила раздела 2, контракт JSON, потоки/память, обработка ошибок декодера, утечки нативных ресурсов, сеть. Выход — список блокеров и рекомендаций.

### red-team / judge
Перед заморозкой: прогон по рубрике жюри, «злые» файлы (mp3/m4a/ogg/wav 8–48 кГц, стерео, 1 спикер, 5 спикеров, 0 речи, 1 час, битый файл), чистая установка, авиарежим. Выход — топ-5 рисков с баллами.

### docs-release
README (установка/использование), ARCHITECTURE.md, MODELS.md (лицензии), LIMITATIONS.md, TEST_RESULTS.md, сценарий видео. Только реальные измерения.
