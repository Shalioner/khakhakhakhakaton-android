# Методика и результаты тестирования

## Методика
- Харнесс `bench` (src/android/bench) гоняет тот же `core` и те же модели, что в APK, через sherpa-onnx Java API и llama.cpp (neurollm.dll) на ПК.
- Метрики — `tools/report.py`: WER и cpWER (без пунктуации, ё→е), DER (collar 250 мс, венгерское сопоставление спикеров), ошибка границ реплик, RTF.
- Тестовые данные — только наши (`testdata/`), записи жюри не используются.

```bash
tools\build_llm_windows.cmd                      # neurollm.dll для LLM на ПК
cd src/android && ./gradlew :bench:run --args="testdata/smoke out/smoke"     # из корня: пути относительно корня репо
python tools/report.py testdata/smoke out/smoke --timings out/smoke/timings.json
```

## Результаты: smoke (2026-11-06)
Набор: 4 синтетических диалога ~45 с, 2 спикера, голоса Windows TTS (Irina, Pavel), 2 чистых + 2 с шумом SNR 10 дБ и перекрытиями. Это **синтетика** — оптимистичная оценка, не замена живым записям.
ПК: Windows 11, 20 потоков (ASR/диаризация 8 потоков, LLM 4). **RTF на телефоне не измерен.**

| конфигурация | WER ср/худш | cpWER ср/худш | DER ср/худш | границы ср, мс | RTF ПК ср/худш |
|---|---|---|---|---|---|
| без LLM | 0.7 / 1.3 | 1.6 / 3.9 | 8.3 / 8.7 | 287 | 0.080 / 0.083 |
| LLM на каждую реплику | 0.7 / 1.3 | 1.6 / 3.9 | 8.3 / 8.7 | 287 | 0.271 / 0.278 |
| **LLM только для неоформленных реплик (по умолчанию)** | 0.7 / 1.3 | 1.6 / 3.9 | 8.3 / 8.7 | 287 | 0.122 / 0.183 |

Выводы:
- LLM не меняет WER по построению (WordGuard), но правка каждой реплики утраивает RTF → по умолчанию LLM вызывается только для реплик без заглавной буквы/завершающего знака.
- DER целиком состоит из miss: концы реплик обрезаются раньше реального конца звука (оценка конца слова по последнему токену). Следующая задача — расширять конец реплики до границы VAD/турна.

## Что ещё не измерено
- Живые записи, 3–5 спикеров, длинные файлы (30–60 мин), 8 кГц, клиппинг, форматы mp3/m4a/ogg/amr.
- RTF и пиковая RAM на телефоне (4–6 ГБ).

## Результаты: синтетическая матрица dev/test (2026-11-07)
Набор: `bash tools/build_synth_matrix.sh` — по 12 файлов в dev и test (разные фразы и seed): 1/2/3/5 спикеров, 1–5 мин, чистые / шум SNR 8 дБ с перекрытиями / телефон 8 кГц / тихая (−26 дБ) / клиппинг. «Дикторы» — 2 голоса Windows TTS (Irina, Pavel) и их варианты со сдвигом высоты/темпа (SSML), поэтому ось `voices`: `distinct` (разные базовые голоса), `same_base` (один голос, разная высота), `mixed`.
ПК x64; RTF телефона не измерен.

### Числа: e2e-модель с пунктуацией vs модель без пунктуации (test)
GigaAM v3 e2e нормализует числа в цифры («три тысячи» → «3 000», «двенадцати» → «12:00»); в наших эталонах числа словами — это почти весь WER на test.
| ASR | WER ср / худш | RTF ПК |
|---|---|---|
| v3 RNNT e2e (пунктуация, цифры) | 7.0 / 9.2 | 0.094 |
| v3 RNNT без пунктуации (слова) | **0.9 / 2.2** | 0.093 |
| v3 RNNT без пунктуации + LLM на каждую реплику | 0.9 / 2.2 | 0.238 |
LLM ставит пунктуацию: из 342 ответов WordGuard принял 259 (76 %), отклонённые 83 остаются в виде ASR (строчные, без знаков). Выбор зависит от того, как записаны числа в эталонах жюри (решение не принято).
