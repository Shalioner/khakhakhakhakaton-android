# Архитектура решения

## Контекст
Android-приложение «Нейро-стенографист» полностью на устройстве превращает аудиозапись разговора в структурированную расшифровку `{"transcript":[{speaker_id,start_ms,end_ms,text}]}`. Сети нет: в манифесте отсутствует `android.permission.INTERNET`, все модели упакованы в APK.

## Компоненты
```
 аудиофайл (SAF) ──► engine-audio ──► PCM16 16 кГц моно (кэш на диске)
                       MediaExtractor/MediaCodec, даунмикс, ресемплинг (windowed sinc),
                       DC-фильтр, нормализация громкости по речевым кадрам
                                │
                                ▼
                    Silero VAD ──► речевые интервалы ──► Chunker (≤25 с, резка только в паузах)
                                │                                   │
              ┌─────────────────┴──────────────┐                    ▼
              ▼ (поток 1)                      ▼ (поток 2)      GigaAM v3 RNNT (e2e, с пунктуацией)
   pyannote-seg-3.0 + CAM++ эмбеддинги   ◄─ параллельно ─►    токены + таймстемпы → слова (TokenWords)
   FastClustering, авто-число спикеров                              │
              │ турны спикеров                                      │ слова в абсолютном времени
              └───────────────────────┬─────────────────────────────┘
                                      ▼
   core: Alignment (слово→спикер по перекрытию, сглаживание) → Segmenter (реплики, пауза > 1 с)
         → SpeakerRelabel (speaker_N по первому появлению, растворение «шумовых» спикеров)
         → уточнение границ по VAD → ContractValidator
                                      ▼
   engine-llm: llama.cpp + Qwen2.5-0.5B Q4_K_M — только регистр/пунктуация для неоформленных реплик,
               каждый ответ через WordGuard; протокол встречи по кнопке
                                      ▼
   app: экран расшифровки (цвет спикера, время, тап = воспроизведение), экспорт JSON через SAF
```

| Модуль | Содержимое | Зависимости |
|---|---|---|
| `core` | чистый Kotlin/JVM: модели данных, Alignment, Segmenter, SpeakerRelabel, TokenWords, Chunker, WordGuard, GuardedEditor, Summarizer, JsonExporter, ContractValidator, DSP, метрики. Все пороги — `PipelineConfig` | — |
| `engine-audio` | декодер Android → `PcmFile` (чтение окнами) | core |
| `engine-sherpa` | обёртки sherpa-onnx 2.0.1: VAD, ASR, диаризация | core, engine-audio, sherpa-onnx AAR |
| `engine-llm` | llama.cpp (статически) + JNI `libneurollm.so`, `LlamaBackend` | core |
| `app` | Compose UI, Foreground Service, `BenchActivity` | всё |
| `bench` | ПК-харнесс: тот же `core` и модели через Java API sherpa-onnx и neurollm.dll | core |

## Основные технические решения
- **ASR — GigaAM v3 RNNT e2e int8** (MIT): лучший опубликованный WER для русского среди моделей, доступных в sherpa-onnx, и сразу выдаёт пунктуацию с регистром. Таймстемпы токенов → слова в абсолютной шкале файла. См. [ADR-0001](ADR/0001-models.md).
- **Тайминги только из аудио**: начала слов — таймстемпы токенов ASR, концы реплик уточняются по границам VAD-сегментов (не дальше 1 с и не залезая на соседнюю реплику). Равномерных распределений нет.
- **Число спикеров не задаётся**: кластеризация с порогом (`numClusters=-1`), затем спикеры с суммарной речью < 1.5 с растворяются в соседях (неречь не порождает спикеров).
- **ASR и диаризация идут параллельно** на раздельных пулах потоков.
- **LLM не может испортить метрики**: она меняет только регистр/пунктуацию; `WordGuard` сравнивает нормализованные слова до/после и откатывает любую иную правку; число/порядок/спикеры/тайминги реплик не трогаются. Вызывается только для реплик, которые ASR не оформил (экономия RTF). См. [ADR-0002](ADR/0002-llm.md).
- **Fallback на каждом шаге**: диаризация упала → один спикер; LLM недоступна/не уложилась в бюджет → текст ASR; нечитаемый файл → понятная ошибка в UI.
- **Длинные файлы**: PCM хранится на диске и читается окнами; обработка в Foreground Service с wake lock, прогрессом и отменой.

## Безопасность и приватность
- Нет разрешения INTERNET и сетевых библиотек; аналитики и крэш-репортеров нет.
- Аудио и расшифровки остаются в приватном хранилище приложения; экспорт — только туда, куда пользователь сам выберет через системный диалог (SAF).
- `allowBackup=false`.
