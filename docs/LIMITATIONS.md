# Ограничения решения

## Поддерживаемые условия
- Android 9+ (minSdk 28), arm64-v8a. Целевое устройство — 4–6 ГБ RAM.
- WAV PCM 8/16/24/32, float32, A-law и mu-law (моно/стерео) декодируются встроенным парсером. WAV с числом каналов больше двух, остальные WAV-подтипы и форматы mp3, m4a/aac, ogg/opus, flac, amr, 3gp зависят от системного MediaCodec устройства; успешное чтение любого произвольного кодека не гарантируется. Вход приводится к 16 кГц моно.
- Русская речь. Число спикеров определяется автоматически.
- Вход: файл из памяти устройства, «Поделиться» из другого приложения или запись с микрофона (WAV 16 кГц).

## Известные ограничения
- **Похожие голоса**: в эксперименте на ПК Nemotron различил два голоса из пяти синтетических дикторов в clean_5spk_000. DER вырос с 32.0 до 50.1 %.
- **Одновременная речь**: в местах перекрытия реплика достаётся одному спикеру; речь второго теряется для диаризации.
- **Границы реплик**: конец последнего слова оценивается по таймстемпу токена и границе VAD; типичная ошибка — десятки–сотни мс.
- **Очень длинные файлы**: Nemotron читает PCM окнами, но резервная диаризация pyannote + CAM++ держит весь сигнал во float в Java-куче (1 час ≈ 230 МБ). При переходе на резервный путь на устройствах с маленьким heap возможен OOM [Проверить на телефоне]; при ошибке приложение при необходимости продолжает с одним говорящим.
- **Неречевые звуки (правило 8 AGENTS.md)**: GigaAM через sherpa-onnx не отдаёт уверенность токенов, поэтому фильтр «одиночный неуверенный токен < 300 мс» не срабатывает; отсев держится на VAD и на том, что ASR не выдаёт слов на неречь. На вставках ESC-50 (кошки, собаки, смех) лишних слов и спикеров не было (testdata/live_dev/meow_*).
- **LLM** маленькая (0.5B): протокол встречи может содержать неточности; на текст расшифровки она влияет только через WordGuard.
- Два прохода ASR (слова + пунктуация) удваивают время распознавания; размер APK ~1.1 ГБ (модели внутри), LLM (~0.5 ГБ) и Nemotron (~0.1 ГБ) дополнительно копируются во внутреннее хранилище при первом использовании.

## Что не входит в текущую версию
- Повторная обработка отдельных фрагментов (переименование говорящих и правка текста реплик уже есть: тап по метке говорящего / долгое нажатие на реплику).
- Аппаратное ускорение (NNAPI/GPU) — только CPU.

## Риски демонстрации
- Mac-сборка v0.2.0 пока не проверена на физическом телефоне. Исторические Pixel-замеры ниже относятся к другим APK, а не к проверке этого файла. Текущее состояние — [отчёт v0.2.0](RELEASE-0.2.0.md).
- Ключ подписи Mac-сборки отличается от v0.1.0: установка поверх старого APK невозможна. Удаление старого приложения стирает его локальную историю и внутренние аудиофайлы; перед самостоятельным удалением сохранить нужные данные по [инструкции](../src/README.md#установка-готового-apk).
- На Pixel 6a с Nemotron по девяти файлам live_test средний / худший DER составил 21.5 / 52.2 %, RTF — 0.41 / 0.55. В таблице замеров указано 734 МБ памяти. [Результаты тестов](TEST_RESULTS.md).
- Первая обработка с LLM дольше из-за копирования модели (~0.5 ГБ).

## Дальнейшее развитие
- Живые записи команды в testdata (разные телефоны, комнаты, 3–5 спикеров).
- A/B моделей эмбеддингов спикеров и CTC vs RNNT для точности таймингов.
- Блочная диаризация длинных файлов с привязкой спикеров по эмбеддингам.
- Объединение VAD по исходному и AGC-сигналу для тихих слов — включать только после проверки по правилу 9 (бывший issue #2).
- Диаризация Nemotron в ПК-стенде `bench` (onnxruntime Java), чтобы цифры ПК совпадали с APK (бывший issue #5).
- Запись с микрофона при заблокированном экране и обработка `onTimeout` foreground-сервиса на Android 15+ (бывший issue #7).
- Слайды защиты (8–12 слайдов, только реальные цифры из [TEST_RESULTS.md](TEST_RESULTS.md)) (бывший issue #9).
- ПК-стенд: пересобрать `neurollm.dll` (`tools/build_llm_windows.cmd`) — текущая сборка падает в `LlamaNative.complete`; до этого прогонять bench с `--llm none`.
